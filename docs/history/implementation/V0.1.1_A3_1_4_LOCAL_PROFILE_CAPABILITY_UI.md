# V0.1.1-A3.1.4 本地 Profile 与能力界面整理

> 文档分类：**HISTORICAL**。历史实施 / 验证记录；数字、限制与能力结论只对应当时版本，不是当前全局状态。 本地 Profile 与 Metadata 原实现记录；当前发布合同不继承旧 Built-in。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

## 修改原因与范围

此前左侧混合显示连接配置、模型能力与本次运行选择，长结果页也使运行控件不易返回。旧的 Ollama 识别会依据 Custom URL 和模型名做特判，可能把未经验证的能力赋给用户配置。本轮调整 Profile 合同、精确能力记录、OpenAI-compatible Adapter、Web 页面及相关定向测试；RAG、Grounding、Domain Rule 和 Orchestrator 业务流程未改。

## 页面与 Custom Profile

- 左侧分为“基础模型配置”“模型能力”和“本次分析输入”。Thinking、Effort、Normal/Streaming 当前选择与对应能力状态位于同一个可折叠区域。桌面端左栏 sticky 且按视口高度独立滚动；窄屏恢复普通页面滚动。
- Custom OpenAI-compatible 只需填写名称、Base URL、Model ID、Deployment；Cloud 另需 Secret 环境变量名，Local 可留空。服务标识和 Adapter 由预设提供，高级连接设置可查看或修改。
- 能力面板显示 Streaming、Thinking、Reasoning Effort、Structured Output、Tool Calling 的状态和证据来源。连接身份在编辑表单中发生变化时，草稿能力立即显示 UNKNOWN；保存后按精确身份重新加载。
- Secret 值不进入浏览器或配置文件。查询模型、连接测试、Streaming Probe 与 Ollama metadata 查询都由单独按钮显式触发。

## UNSET 与 UNKNOWN

请求不设置高级选项时，Adapter 仅发送基础 Chat 参数；Custom Profile 即使所有高级能力 UNKNOWN，也可执行 Normal 请求。显式选择 Thinking ON/OFF、Reasoning Effort 或 Streaming 时，才按对应 Capability 校验。AUTO 表示不发送 Thinking 控制参数；内置 Ollama 的默认 OFF 则是明确的本次运行策略。

## 精确身份与本地 Ollama

能力记录绑定 `service_id + adapter_id + base_url + exact model`。Base URL 统一 scheme/host 大小写并去掉路径末尾斜杠；读取时也会兼容扫描此前按原始 URL 拼写保存的记录。旧的三字段 Streaming 本地记录不会自动继承到新身份；需针对当前 Profile 重新 Probe。Custom 不再凭 URL、服务名或相似模型名获得高级能力。

新增只读内置 `Ollama Qwen3.5 4B（本地）`：`ollama / generic_openai_chat / http://127.0.0.1:11434/v1 / qwen3.5:4b`，不需要 Secret。当前记录了用户已观察到的精确模型 metadata：`thinking.values=[false,true]`、`thinking.default=true`，来源为 `MODEL_METADATA`；这些值不推广到其他模型。页面可显式调用 `/api/show` 刷新该模型的 Thinking metadata，成功后以无 Secret 的本地记录保存。ON/OFF 另有独立实机验证按钮，每次均需用户确认并各发起一次最小 Chat 请求；仅成功的方向会单独记录为 `USER_VERIFIED`。Probe 仅为该次请求临时放行 UNKNOWN，普通请求仍使用持久化的 Capability gate。创建页面或普通分析时不会自动查询或发送 Probe。

该内置 Profile 默认 Thinking OFF、Response Mode Normal。Adapter 对其将 OFF 映射为 OpenAI-compatible 请求中的 `reasoning_effort="none"`，ON 映射为 `"high"`，AUTO 不发送控制；Ollama 特有映射仅在 Adapter 内。当前 metadata 刷新与实机映射只开放给精确的 Ollama `qwen3.5:4b`。此默认值旨在避免此前观察到的默认 Thinking 导致的长响应和 `READ_TIMEOUT`。本轮未发起真实 Ollama 请求，API 关闭 Thinking 的实际效果仍需页面人工验证。Streaming 能力与 Thinking 独立，默认仍是 UNKNOWN，需要单独显式 Probe。

## 本轮复核与限制

内置 Profile JSON 中的精确能力声明本身正确；复核时当前后端序列化也已返回 ON/OFF `SUPPORTED`、来源 `MODEL_METADATA`、模型默认 ON。另发现持久化记录直接按 URL 原文 hash，`/v1/` 与 `/v1` 会查到不同记录，已增加规范化与旧记录兼容读取。若仍运行旧 Web 进程，需要重启以载入新后端代码。

本轮只运行相关离线 Python、Node 测试和 JavaScript 语法检查；不发真实 Cloud 请求，也不自动发起真实 Ollama 生成请求，不跑全量回归。metadata 解析以用户提供的本机观测结构和 Fake HTTP 响应验证。不同 Ollama 版本或其他模型的 `/api/show` 字段及 Thinking 参数效果尚未实机验证。Tool Calling、Structured Output Probe 和通用在线能力发现未实现。
