# V0.1.1-A3.1：应用级流式分析与 Profile 页面整理

> 文档分类：**HISTORICAL**。历史实施 / 验证记录；数字、限制与能力结论只对应当时版本，不是当前全局状态。 保留应用 SSE 首次实现；无取消/无 reasoning 的当时限制已被后续替代。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

## 实施范围

本轮保留原有 Normal 分析接口，新增应用级 Streaming。两种模式使用同一 `AnalysisRequest`、水质场景、`DiagnosisService`、知识检索、Prompt 构造及 `AnalysisResult` 合同。流式模式由 `Orchestrator.analyze_stream()` 调用 `ModelGateway.stream()`；Web 层仅做输入门禁和 SSE 事件转发。未修改 RAG 排序、Grounding 提示要求或领域规则。

Profile 新建时清空旧字段，Provider 初始为“请选择 Provider”。选择 Qwen 或 DeepSeek 后填入对应 Base URL 和推荐 Secret 环境变量名，Model ID 留空供模型查询或手工填写；Custom OpenAI-compatible 保留手工地址和模型。`provider_id`、`adapter_id`、`secret_env`、`deployment` 放在默认折叠的“高级连接设置”中。删除按钮缩小，删除仍需浏览器确认。

## 流式数据流与页面

`AnalysisRequest → Orchestrator → ModelGateway.stream() → OpenAICompatibleAdapter / MockGateway`。应用依次发出 `analysis_started`、`facts_ready`、`rules_ready`、`evidence_ready`，再转发 `content_delta` 和可用的 `usage`，最后发出 `completed` 或安全的 `failed`。Provider 未返回 Usage 时发出 `source: unavailable`，不把缺失值显示为 0。最终正文沿用现有 JSON 解析，生成结构化结果并记录允许字段的 JSONL Trace。

页面增加 Normal / Streaming 选择。Streaming 先展示观测事实、规则与 RAG 背景证据，随后逐段追加模型正文；完成后显示推断、建议、不确定性、解析状态、TTFT、总耗时和 Token Usage。TTFT 从请求开始到首个正文 delta 计算，包含事实准备、检索和模型等待时间。提交期间禁用“开始分析”按钮。流中失败时保留已经收到的正文，显示安全错误码；浏览器连接意外断开时显示 `STREAM_INTERRUPTED`。

## 网络与 Secret 边界

真实 Profile 仍须勾选 **REAL NETWORK REQUEST**；Cloud Secret 只从启动时加载的环境变量取得，页面和 SSE 不返回其值。错误只显示受限错误码，不转发 SDK 原始异常。现有真实 Profile 的 Streaming Capability 仍为 `UNKNOWN`，Adapter 会在创建传输前返回 `OPTION_UNKNOWN`。本轮没有把真实流式能力标为已验证，也没有执行真实 Cloud 请求。Mock Streaming 可完全离线运行。

## 当前限制与后续

本轮不展示 reasoning delta，不提供浏览器取消请求后的应用级取消语义；模型正文的结构化解析仍在完整输出后执行。真实 Qwen、DeepSeek 或自定义服务的流式兼容性需按模型和 Base URL 独立验证，再对精确 Profile 声明 Capability。现有离线测试只证明应用编排与浏览器传输路径，不代表真实服务已通过流式验证。
