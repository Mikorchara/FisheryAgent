# V0.1 工程加固报告

> 文档分类：**HISTORICAL**。历史实施 / 验证记录；数字、限制与能力结论只对应当时版本，不是当前全局状态。 保留 SDK、包资源、Quality/Freshness 加固历史；真实运行待验证是当时状态。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

## IMPLEMENTED

- 将 OpenAI 兼容 Chat Completions 的 HTTP 与 SSE 处理交给官方 OpenAI Python SDK。`OpenAICompatibleAdapter` 是唯一直接导入 SDK 的应用源文件。SDK 自动重试设为 0；Gateway 在未输出流式正文前可按 Profile 重试，已输出正文后不再重试。
- 保留 `ModelGateway` 合同、`MockGateway`、`ModelProfile`、不可变 `RuntimeSnapshot`、Cloud/Local Profile 与现有 `AnalysisResult` 编排。
- 将知识与 Mock JSON 移入 Python 包，通过 `importlib.resources` 读取。Trace 默认写入当前工作目录的 `outputs/`，避免在安装包目录写入。
- 将水质有效性 `Quality(valid/partial/invalid)` 与新鲜度 `Freshness(fresh/stale)` 分离；增加确定性 `partial_stale` 场景，诊断同时产生两个规则结果。
- 使用轻量 `ObservedFacts` 包装水质事实，并预留可选 `detection_summary`。Detection、历史与工具结果仍未进入默认编排。
- 支持纯 JSON 和完整 Markdown JSON 代码块的模型输出。解析失败时保留原始 `generated_text`，设置 `structured_parse_ok=false`，Trace 仅记录解析状态，不记录正文。
- 更新 `.gitignore`，忽略 wheel 构建时产生的 `build/`。

## ARCHITECTURE IMPACT

应用层仍只依赖 `ModelGateway` 合同。SDK 和 HTTPX 只在 OpenAI 兼容适配器中负责传输与流式协议；诊断、RAG、Profile 路由、固定编排和 JSONL Trace 保持原有职责。运行依赖在 `pyproject.toml` 声明为 `openai>=1.0,<3.0` 与 `httpx>=0.27,<1.0`；HTTPX 用于分别设置连接与读取超时。未添加 `requirements.txt`，由 `pyproject.toml` 作为单一依赖声明。

## RISKS

- OpenAI 兼容服务对 Chat Completions、流式 Usage 和错误响应的实现可能不同；目前仅用离线假客户端验证，需在目标服务上单独做连接验证。
- `total_timeout_s` 在应用侧按请求期限检查；单次 SDK 调用仍受 HTTPX 分项超时约束，不能保证精确的硬截止时间。
- 依赖使用版本范围，新的开发环境能安装，但不会精确复现此次安装的每个传递依赖版本。若未来需要严格复现，应再决定锁文件策略。
- 知识 JSON 缺少逐块文献来源；现有 `legacy` 来源标识继续保留。
