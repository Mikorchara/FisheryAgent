# V0.1.1-A3.1.6 能力界面整理与运行默认值

## 实施内容

- Profile 信息按身份、能力和运行偏好呈现。Capability 仍按精确服务、Adapter、Base URL 与模型绑定；偏好不会写成能力证据。
- Custom Profile 保存 `default_thinking_mode` 与 `default_response_mode`。旧配置文件继续按 AUTO / Normal 读取；偏好保存在 Git 忽略目录的 Custom Profile 文件中，不含 Secret 值。
- Built-in Profile 的默认定义和能力仍只读；页面上的 Thinking 与 Normal / Streaming 选择只作用于本次请求。
- Profile 切换时，服务端提供精确 Profile 的 Capability 和有效默认值；页面按默认值恢复运行选项。未知或冲突的默认值在运行时回退为 AUTO + Normal 并显示提示，原 Custom 偏好仍保留。明确记录为 UNSUPPORTED 的偏好在保存时返回字段级 `PROFILE_DEFAULT_CONFLICT`。
- 更改 Custom Profile 身份字段后，界面立即清除旧能力显示和验证入口，并把当前运行选择回退到 AUTO + Normal。保存后旧身份的 `USER_VERIFIED` 记录不会迁移到新身份。
- Thinking / Streaming 处于 UNKNOWN 时保留主要验证入口；对应结果来源为 `USER_VERIFIED` 后，主要入口隐藏，重新验证入口收纳在默认折叠的“高级验证操作”中。Streaming 服务端只接受对当前精确身份已有 USER_VERIFIED 记录的显式重新验证。
- Ollama metadata 查询也放入次级验证区域。页面分别展示 ON / OFF 的证据来源、模型声明的支持值和模型默认值；`MODEL_METADATA` 不替代 `USER_VERIFIED`。

## 尚存限制

- 当前 Custom Runtime Defaults 仅包含 Thinking 与响应模式；尚未增加 Effort 或采样参数默认值。
- ON / OFF 实机 Thinking Probe 仍仅适用于现有精确 Ollama Qwen 3.5 4B Profile。
- `UNKNOWN` 偏好会保存在配置中，但在该精确能力被验证为 SUPPORTED 前，页面和请求会使用安全默认值。
