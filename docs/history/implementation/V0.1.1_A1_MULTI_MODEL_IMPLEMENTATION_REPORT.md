# V0.1.1-A1 多模型 Runtime 合同与能力校验实施报告

> 文档分类：**HISTORICAL**。历史实施 / 验证记录；数字、限制与能力结论只对应当时版本，不是当前全局状态。 初版多模型参数与 Usage 合同的实施和离线验证历史。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

本报告记录本轮 Prototype 内的实现。正式项目 `D:\Fishery_Project` 保持只读；没有使用真实 API Key、连接模型服务、下载模型、提交或推送。此阶段为以后真实外接 LLM 验证准备合同，**不代表任何真实 Provider 或模型已经验证可用**。

## IMPLEMENTED

- 在 Profile 中分开记录 `provider_id`、`adapter_id`、精确 `model`、`base_url` 和部署标签。旧字段 `provider_kind` 仅作 Cloud/Local 部署标签保留；不再用于判断厂商。
- 新增 `GenerationOptions`（可选输出上限、temperature、top_p）与 `ReasoningOptions`（AUTO/ON/OFF、按模型声明的 effort 字符串），并从 `AnalysisRequest` 贯通到网关。未设置的字段不发送；`AUTO` 不等于显式 `OFF`。
- 新增三态 `ModelCapabilities` 和小型纯函数 `validate_options()`。它们区分支持、不支持、未知；冲突是当前请求的校验结果，不是永久能力。配置中的声明绑定 Base URL 与精确模型，变更任一身份不能继承旧声明。
- `OpenAICompatibleAdapter` 继续独占 OpenAI SDK。它先校验，后按 Capability 将输出上限映射到明确声明的 `max_tokens` 或 `max_completion_tokens`；仅对匹配身份的 DeepSeek/Qwen 使用受控思考开关映射。通用自定义接口没有未经声明的高级参数。
- Orchestrator 移除旧的 Chat/Advice 固定 `max_tokens`。固定水质诊断、RAG 和 AnalysisResult 流程保持原样。Option 错误以 `error_code` 和不含 Secret 的 `error_option` 返回并记录。
- `Usage` 支持输入、输出、总 Token，以及可选思考 Token、缓存输入 Token 和来源。Provider 没有返回的数据保持 `None/unavailable`；Mock 不估算。新增进程内 `UsageAccumulator`，供验证会话累计。CLI Demo 明示单请求和会话统计。
- 网络阻断除连接与发送外，也覆盖 DNS 解析；默认测试和 Mock Demo 均不会调用真实 API。

## PROFILE MODEL

| 字段 | 含义 |
| --- | --- |
| `provider_id` | 厂商/运行时身份，如 `deepseek` 或 `custom`；用于隔离受控专项映射。 |
| `adapter_id` | 协议身份：`openai_chat` 或 `generic_openai_chat`；当前均由同一个适配器实现。 |
| `base_url + model` | Capability、验证记录和默认参数的精确作用域。 |
| `provider_kind` | 向后兼容的部署标签，示例值为 `cloud/local`；命名留待后续小迁移。 |
| `secret_env` | 环境变量名；Profile 不保存真实 Key。 |
| `profile_status` | VERIFIED、EXPERIMENTAL 或 CUSTOM。 |

Profile 和 RuntimeSnapshot 均不可变。Registry 在请求开始时生成快照；之后修改 Profile 不改变已开始请求。真正 VERIFIED 配置需要 `source=user_verified`、验证日期、精确模型和地址作用域；修改模型或地址时原验证信息不能沿用。当前仓库没有真实 VERIFIED 预设。Mock 资源里的 `cloud-demo` 为 EXPERIMENTAL，`local-demo` 为 CUSTOM；名称、地址与模型均是演示输入，不代表已经联网成功。

## VERIFIED / EXPERIMENTAL / CUSTOM SEMANTICS

- **VERIFIED**：用户已按当前地址和精确模型完成验证，可保存经校验的默认生成/思考选项，供人工选择作为稳定方案。不会自动跨 Provider 故障切换。修改关键身份时必须重新建立验证记录。
- **EXPERIMENTAL**：用于官方文档线索或待测方案，允许明确标注的静态能力声明，但不携带“已验证默认高级参数”。
- **CUSTOM**：自定义兼容地址与模型；高级能力默认 UNKNOWN。普通请求只需最小 Chat Completions 字段；用户显式请求的未知高级字段被拒绝。

一次成功的 HTTP 200 不等于所有高级能力 VERIFIED。正式项目的 Provider 预设不能证明用户曾成功使用哪三家服务。

## CAPABILITY MODEL

三态字段覆盖 streaming、temperature、top_p、输出上限、reasoning、reasoning toggle、reasoning effort，并为 structured output、tool calling、streaming usage 留出声明位；后面三项本轮未实现功能。Effort 合法值是当前精确模型的字符串集合，不声称不同厂商同名档位等价。Capability 来源限于 `user_verified/official_docs/experimental/unknown`，可记验证日期；本轮没有在线发现服务或独立模型数据库。

## PARAMETER VALIDATION

- `SUPPORTED`：仅在当前精确模型和地址的声明范围内允许发送。
- `UNSUPPORTED`：显式请求返回 `OPTION_UNSUPPORTED`。
- `UNKNOWN`：显式请求返回 `OPTION_UNKNOWN`；未设置或 `AUTO` 不因此失败。
- `CONFLICT`：仅对本次组合返回 `OPTION_CONFLICT`，例如已声明“开启思考与 temperature 冲突”时同时显式设置两项。
- 数值或 effort 档位不合法返回 `INVALID_OPTION_VALUE`。系统不静默删除显式选项，也不把未知高级参数透传给服务。

## ADAPTER MAPPING

- 通用 `generic_openai_chat` 在默认非流式请求中只发送 `model/messages`。`stream=True` 仅在当前精确模型显式声明支持时发送。
- 输出上限只在 Capability 为 SUPPORTED 且已声明原始字段名时发送；因此 Generic 的 `None` 不强制发旧版 `max_tokens`。
- DeepSeek 的 `thinking.type` 与 Qwen 的 `enable_thinking` 仅由 `OpenAICompatibleAdapter` 对匹配 `provider_id + adapter_id` 翻译，仍需当前模型能力许可。这个映射是协议准备，不是对示例模型的真实可用性宣称。
- 不开放全局 `extra_body` 或跨厂商原始参数字典；也没有建立多个按厂商命名的适配器。

## USAGE / TOKEN ACCOUNTING

`AnalysisResult.usage`、JSONL Trace 和 CLI 可显示 `input_tokens/output_tokens/total_tokens` 及可选 `reasoning_tokens/cached_input_tokens`。适配器只映射 Provider 实际返回的字段。缺失字段为 `None`，来源为 `unavailable`，显示时写 `unavailable`；不把缺失误写为 0。流式响应若最后事件含 Usage，会保留在该事件中；若服务不返回，保持不可用。是否请求额外的流式 Usage 字段由 Capability 决定，Generic 默认不加。

`UsageAccumulator` 可累计当前进程内多个请求。只在每个请求均返回相应 Provider 数值时给出完整会话总数；有缺失则该会话总数为 unavailable，并保留请求总数/已报告数。没有持久化、Memory、Token 估算或费用计算。

## NOT IMPLEMENTED

自动跨 Provider failover、Web Developer UI、Tool Calling、Agent Loop、Memory、向量数据库、Fine-tuning、费用计算、在线能力发现、模型登记服务、复杂 Adapter Registry、全局 raw `extra_body`、本地模型安装、真实 Provider/Local 连接、生产项目集成与应用层流式显示均未实现。

## RISKS

1. 当前 Profile 示例没有经过真实 API 验证，静态 Capability 声明不能代替真实测试。特别是 Provider 对思考开关、输出上限和流式 Usage 的实际接受方式可能因精确模型或版本而异。
2. `provider_kind` 是历史字段名，本轮将其值限于 Cloud/Local 部署标签，但还没有删除或重命名该字段，以保持现有结果合同兼容。
3. 通用兼容服务可能不接受 `stream` 或任何输出上限字段，故 Generic 默认高级能力 UNKNOWN；真实接入时需逐项验证。
4. 会话 Usage 仅是内存累计；它不关联长期对话上下文。Provider 不返回完整 Usage 时，不能保证会话统计完整。
