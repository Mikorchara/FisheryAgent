# V0.1.1-A3.0 Developer Validation Web UI

## UI 架构

这是只在本机使用的开发验证页面，不是正式 Fishery 产品界面。Flask 提供页面、静态资源和两个 JSON 接口；HTML/CSS/少量 JavaScript 负责表单与结果展示，不引入前端构建工具。Web 层不导入 OpenAI SDK，也不按 Qwen/DeepSeek 分支实现业务规则。

请求路径：页面选择 Profile、已有 Mock 水质场景与问题 → `POST /api/analyze` → `AnalysisRequest` → 现有 `Orchestrator` → `MockRepository`、`DiagnosisService`、`KnowledgeService` → `MockGateway` 或 `OpenAICompatibleAdapter` → `AnalysisResult` → 白名单 JSONL Trace。Gateway 的选择只区分离线 Mock 与显式 Cloud 请求；Provider 差异由 Profile/Capability/Adapter 处理。

## 页面功能

- Runtime / Model：Mock 离线、Qwen `qwen-plus`、DeepSeek `deepseek-flash`。两个 Cloud Profile 均为 **EXPERIMENTAL**，高级能力默认不随基础连接成功而开放。
- Scenario：直接来自现有 `scenarios.json` 的 `normal`、`low_oxygen`、`partial`、`stale`、`partial_stale`。
- 输入一个问题，执行现有非流式 Chat 分析；默认选择 Mock。
- 展示模型正文、Observed Facts（水温、pH、溶氧、质量、新鲜度、时间与来源）、Rule Results（code、severity、message、版本）、RAG Evidence（ID、来源、文本、score）、Structured Result（inference、recommendations、uncertainty、解析状态）及 Runtime/Usage/总耗时。Provider 未报告的 Usage 显示 `unavailable`，不误写 0。
- Cloud 请求有醒目的 **REAL NETWORK REQUEST** 提示和逐次确认框；服务器也验证确认标记。Secret 缺失返回 `SECRET_MISSING`，其他模型错误仅显示安全错误码，不传出 SDK 原始异常。

## 启动

在工作区根目录：

```powershell
.\.venv\Scripts\python.exe -m pip install -e .
.\.venv\Scripts\python.exe -m fishery_ai web
```

浏览器打开 `http://127.0.0.1:8765`。服务只绑定 `127.0.0.1`，不启用 debug 或自动重载。`--port` 可换端口。首次启动不会自动发起 Cloud 请求。停止终端进程即可关闭页面。

## Secret 与数据边界

Web 启动入口只从当前工作目录 `.env` 装入两项已知 Secret 环境变量，且不覆盖已有环境变量；`create_app()` 本身不读取 `.env`。Profile JSON 仅含 `secret_env` 名称。`GET /api/config` 只返回公开的 Profile 元数据，浏览器请求与响应均不包含 Key；页面无 Key 输入框。`result_to_dict()` 只序列化公开的 `RuntimeInfo`。Trace 白名单不含 API Key、完整 Prompt 或模型正文，写在被 Git 忽略的 `outputs/`。页面以 `textContent` 填入模型文本，避免将其作为 HTML 执行。

本地页面没有身份认证，仅适合受控开发机。Cloud 请求会发送现有 Mock 水质事实、规则摘要、RAG 证据和用户问题到所选服务；点击前需明确确认。正式生产数据没有接入。

## 测试与当前限制

Cloud Runtime checkpoint 已在开发 UI 前提交并推送到 `origin/main`：`2ea48b0`；没有修改 v0.1 tag。UI 修改保持未提交。A3 新增测试使用 Flask 进程内客户端和假 Gateway，并阻断 socket/DNS；覆盖应用创建、页面与 Profile 元数据、Mock 全流程、Qwen/DeepSeek Profile 切换、确认与缺失 Secret、安全错误、Usage 缺失值。全量离线测试 **57 项通过**。本地 HTTP 冒烟检查中，页面、CSS、JS、配置接口与 Mock `low_oxygen` 分析均返回 200，分析状态 completed，规则 1 条、证据 5 条、Usage 为 unavailable。没有进行真实 Cloud 调用。

浏览器自动化所需的工作区外插件说明文件读取被自动审批拒绝；因此本轮通过 HTTP 冒烟检查和 Flask 测试客户端验证功能，**未完成目视排版验证**。

当前没有应用层 Streaming、思考实时显示、Tool Calling、Agent、Memory、Fine-tuning、Local Ollama、Profile 编辑器、Capability Probe、API Key 输入框、认证或正式前端框架。Cloud 的结构化输出是否稳定仍需人工验证。

## 下一步

先由开发者在本机以 Mock 检查页面和结果字段；如需真实 Cloud 全链路验证，再逐次确认请求并核查结构化输出、Usage 与 Trace。后续才考虑应用层 Streaming 或更细的 Capability 显示，不将此页面直接作为正式产品界面。
