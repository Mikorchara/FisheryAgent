# V0.1.1-A3.1.5 Capability UI 与 Thinking 验证

> 文档分类：**HISTORICAL**。历史实施 / 验证记录；数字、限制与能力结论只对应当时版本，不是当前全局状态。 URL 规范化与 ON/OFF 独立 Probe 首轮实施；当前由 R4/R5 统一。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

## 根因与修复

内置 Ollama Profile 的 metadata 定义本身是精确且正确的。复核当前服务序列化结果时，ON/OFF 均为 `SUPPORTED`、默认 ON、来源 `MODEL_METADATA`。能力文件身份此前使用原始 Base URL 计算 hash；以 `/v1/` 保存的记录无法按 `/v1` 查找，且没有规范化比较。本轮统一 Base URL scheme/host 大小写和路径末尾斜杠，并兼容扫描旧 URL 拼写记录。若现有页面仍显示旧状态，需重启此前启动的 Web 进程。

## UI 与验证流程

“02 · 模型能力”现在是一个可折叠区域，同时包含各能力状态、来源、默认/支持值及 Thinking、Effort、Normal/Streaming 的本次选择。Built-in 连接和 Capability 定义仍只读；用户可调整当前请求选项。

Ollama `qwen3.5:4b` 有独立的 metadata 刷新入口，以及 Thinking ON、OFF 两个单独的实机 Probe 按钮。每次 Probe 都要求用户确认，只发送一个最小 Chat 请求，重试为 0；只在该方向请求成功后，才记录对应的 `USER_VERIFIED`。本轮测试只使用 Fake Gateway，没有执行真实生成请求。普通分析仍不能绕过 UNKNOWN gate。

如果实机 Probe 确认某个默认 Thinking 方向为 UNSUPPORTED，Profile 默认会退回 AUTO，避免继续发送已被验证为不支持的控制参数。

## 定向验证

已覆盖：内置 Ollama metadata 加载、`/v1/` identity 兼容、ON/OFF 独立证据、显式 Probe 临时 gate、Custom UNKNOWN 基础 Normal 请求、Built-in 只读、运行选择与能力面板同区、Streaming Probe 既有行为。所有测试均离线；没有运行全量测试，也未调用 Cloud 或 Ollama 生成接口。
