# V0.1.1-A3.1.2：Profile Manager 简化与同步修复

## 问题与修复

顶部 Runtime / Model 切换原本只更新概要、操作按钮和 Secret 状态；配置表单只有点击“编辑所选”才读取实际字段。因此顶部选择与管理区可能指向不同 Profile。现在所有 Profile 均可通过只读详情接口获取安全的配置字段。顶部切换会立即加载所选 Profile，显示实际名称、Provider、Base URL、Model、`secret_env` 变量名和部署类型。请求带页面版本校验，旧响应晚到时不会覆盖新选择或“新建”的空表单。

页面分为查看、新建和编辑三种状态。预置 Profile 只能查看；User Custom Profile 可点击“编辑所选”修改连接参数或确认后删除；编辑时 Display Name 只读。“新建”清空 Provider、名称、地址、模型及旧连接状态。删除仍归档到 `outputs/custom_profiles/archive/`。同时修复了配置按钮和字段监听中两处误用 JavaScript 逗号表达式的问题。

## 名称规则

新建必须提交非空、唯一的 Display Name；名称按不区分大小写的方式检查，包含 Built-in 与 User Custom Profile。重名直接返回 `PROFILE_NAME_EXISTS`，不再根据相同 Provider、地址和模型触发冲突流程。创建后名称不能修改；页面将字段设为只读，服务端和本地存储层也拒绝改名，返回 `PROFILE_NAME_IMMUTABLE`。需要改名时，先删除原自定义配置，再以新名称创建。服务启动时也检查已加载配置是否存在重名。

已移除“更新原配置 / 另存为副本 / 取消”面板、`conflict_action` 接口语义和自动生成“副本 1 / 副本 2”的逻辑。相同连接参数可以使用不同名称创建；不会自动覆盖或重命名现有配置。Built-in 配置仍不允许编辑或删除。

## 验证与范围

- Python 离线测试：84 项通过，覆盖重名拒绝、创建后不可改名、Built-in 只读、自定义连接编辑与删除。
- JavaScript 离线测试：8 项通过，覆盖顶部选择与表单同步、新建清空、编辑名称只读、旧响应不覆盖新状态和重名提示；原有 Streaming 测试继续通过。
- 本地 Edge 浏览器验证：顶部切换到 Qwen 后配置区同步，点击“新建”后关键字段为空；Mock Streaming 仍完成。没有调用真实 Cloud API。
- 本轮仅修改 Profile Manager 页面、Profile API、用户配置存储、测试和文档；未修改 Streaming、RAG、Grounding、Orchestrator 或正式项目。
