# V0.1.1-A3.1.1：Streaming 修复与 Profile 冲突保护

> 文档分类：**OBSOLETE**。Historical / Superseded：旧方案已被替代，仅归档回查，不再作为操作依据。 旧 Built-in 冲突对话框策略已移除；Streaming bug 诊断过程保留供回查。 当前边界见[架构总览](../../architecture/CURRENT_ARCHITECTURE.md)。

## 已修复问题

### Built-in / Custom 冲突

原页面在冲突对象为 Built-in Profile 时仅禁用“更新原配置”，因此灰色按钮仍可见。现在服务端返回明确的 `allowed_actions`：Built-in 冲突只允许 `copy / cancel`；User Custom 冲突允许 `update / copy / cancel`。页面据此隐藏 Built-in 冲突的“更新原配置”。服务端也拒绝伪造的 Built-in 更新请求，返回 `PROFILE_NOT_EDITABLE`；当 Built-in 名称与另一个 User Custom 的连接同时冲突时，优先保护 Built-in。Built-in 文件始终只读，自定义副本写入被 Git 忽略的用户配置目录。

### Streaming 的浏览器根因

实际 Edge 页面复现了此前的 `NETWORK_ERROR`。`prepareStreamView()` 原本用带逗号的括号表达式枚举结果区 ID；JavaScript 逗号运算只保留最后一个字符串 `"runtime"`，循环逐字符查找 `r`、`u` 等不存在的元素，随后对 `null` 调用 `replaceChildren()`。这发生在 `fetch` 之前，因此此前页面没有真正建立该次 Streaming 请求。现已改为数组枚举。

原外层捕获还把任意页面异常都显示成 `NETWORK_ERROR`。现在 HTTP 预检错误保留安全错误码，SSE `failed` 事件显示 `OPTION_UNKNOWN`、`OPTION_UNSUPPORTED` 等原有码；读取中断显示 `STREAM_INTERRUPTED`，事件格式和页面渲染错误分别显示 `STREAM_PROTOCOL_ERROR`、`STREAM_DISPLAY_ERROR`。只有未分类的浏览器请求失败继续显示 `NETWORK_ERROR`。

## 链路验证

- Flask Mock SSE：HTTP 200，`text/event-stream; charset=utf-8`，`Cache-Control: no-store`，`X-Accel-Buffering: no`；事件顺序包含 `analysis_started → facts_ready → rules_ready → evidence_ready → content_delta → usage → completed`。
- 真实 Edge 浏览器通过本地 `127.0.0.1` 访问 Mock 页面。修复前状态为 `NETWORK_ERROR`，定位到 `replaceChildren()` 异常；修复后状态为“流式分析完成”，模型正文长度 129 字符，事实区显示 9 个字段。
- Normal 与 Streaming 使用相同的 Profile 选择、Secret 检查和 **REAL NETWORK REQUEST** 确认。离线测试覆盖这两条路径；未更改 RAG、Grounding 或 Domain Rule。
