## MODEL ID MIGRATION

当前独立 DeepSeek Experimental Profile 的请求模型从 `deepseek-v4-flash` 更新为 `deepseek-flash`，Capability 作用域中的 `model_id` 同步更新。`profile_status` 仍为 **EXPERIMENTAL**，`max_retries=0`。Profile ID 保留旧字符串以避免破坏现有验证入口；它只是配置标识，不是发送给 Provider 的模型 ID。Mock Demo Profile 没有变更。历史 [A2 报告](V0.1.1_A2_DEEPSEEK_VALIDATION_REPORT.md)记录的旧请求 ID 未改写。

A2 曾以旧 ID 发送请求，成功响应返回 `deepseek-flash`。据此，本 Profile 将 `reasoning_on=SUPPORTED`，但整体 `source` 仍为 `experimental`，且没有提升 VERIFIED：这一项来自 **A2 用户实测经兼容路由返回的新模型**，并非本轮以新请求 ID 完成的直接复测。Basic Chat、AUTO、ON 的历史成功仅在此边界内标为已验证。`reasoning_off` 和 `reasoning_effort` 仍为 UNKNOWN。

## REASONING CAPABILITY CONTRACT CHANGE

- `ReasoningOptions.mode=AUTO` 不发送开关，也不检查 ON/OFF 的支持状态。
- 显式 ON 只检查 `ModelCapabilities.reasoning_on`；显式 OFF 只检查 `reasoning_off`。
- 每个方向独立取 `SUPPORTED`、`UNSUPPORTED` 或 `UNKNOWN`。未知返回 `OPTION_UNKNOWN`，不支持返回 `OPTION_UNSUPPORTED`；不再由单一 `reasoning_toggle` 推断两个方向。
- `effort` 必须搭配 ON；无效组合先报 `OPTION_CONFLICT`。已声明的 ON + temperature 冲突由本地校验拒绝，不发送已知无效请求。

离线用例覆盖 ON 支持／OFF 未知、两者均支持、ON 不支持／OFF 支持、两者未知或不支持，以及 DeepSeek `thinking.type=enabled/disabled` 的受控映射。业务编排和默认 Mock 流程未增加 Provider 分支。

## NETWORK DIAGNOSTICS

显式执行 `validate-real --check network --confirm-network`，固定主机 `api.deepseek.com:443`；按 DNS、TCP、TLS、一次已鉴权 SDK `/models` 的顺序执行。只输出主机、端口、阶段、耗时和安全错误码；不输出地址列表、原始异常、请求头、Prompt 或响应错误体。

| 阶段 | 结果 | 耗时 | 安全诊断 |
| --- | --- | ---: | --- |
| DNS | 成功 | 46 ms | 可解析主机 |
| TCP 443 | 成功 | 47 ms | 可建立直连 socket |

## ERROR MAPPING

适配器只按 SDK/httpx/socket/ssl **异常类型**判断，不展示或记录异常原文。新增或细化：`DNS_ERROR`、`CONNECT_TIMEOUT`、`READ_TIMEOUT`、`TIMEOUT`、`TOTAL_TIMEOUT`、`TLS_ERROR`、`PROXY_ERROR`、`CONNECTION_ERROR`；Provider 状态仍为 `HTTP_<status>`，异常响应结构仍为 `INVALID_RESPONSE`。`TOTAL_TIMEOUT` 表示整体截止时间已过；`TIMEOUT` 表示 SDK 超时但底层阶段不明。网关对明确可重试错误保留既有“流式正文开始后不自动重试”规则。当前真实 Profile 和 SDK 都设置重试 0。

错误码和诊断行不包含 Key、Authorization、完整 URL query、原始响应错误体或 Prompt。`/models` 本轮返回 `CONNECT_TIMEOUT`，因此没有 HTTP 状态；不能将其误记为认证失败或参数拒绝。
