# V0.1.1-A3.1.3：Capability 与 Provider Identity 修正

## 身份合同

Profile 与运行时现在分别保留 `service_id`（API 服务平台）、`model` / `model_id`（精确模型）及 `model_family`（模型家族）。`provider_id` 暂作兼容字段；旧值 `qwen` 迁移为 `service_id=dashscope, model_family=qwen`，`deepseek` 迁移为 `service_id=deepseek_api, model_family=deepseek`。未知服务或家族不根据模型名称猜测。Capability 绑定包含 `service_id + base_url + model`。

自定义 Profile 文件兼容旧 `provider_id` 格式，下一次保存时使用 `service_id` 和 `model_family` 新合同。Generic OpenAI-compatible Profile 默认 `service_id=custom, model_family=unknown`；模型家族不会带入 capability。

## Capability 证据与验证

支持状态仍是 `SUPPORTED / UNSUPPORTED / UNKNOWN`。证据来源为 `OFFICIAL_DOCS / USER_VERIFIED / UNKNOWN`；Capability 合同支持逐项 evidence 覆盖，旧 Profile 的全局 `source` 仍兼容读取。

- Qwen Plus 精确 Profile：Streaming 为 `SUPPORTED / USER_VERIFIED`。
- DeepSeek Flash 精确 Profile：Streaming 为 `SUPPORTED / OFFICIAL_DOCS`。
- 未验证的 Custom Profile：Streaming 仍为 `UNKNOWN / UNKNOWN`。

未知 Streaming 能力可以由页面按钮显式验证。按钮会清楚提示真实请求和 Cloud 费用，并要求二次确认。Probe 对该次请求临时放行 Adapter gate；普通分析流程不绕过 gate。仅收到实际内容且流正常结束后，才把记录保存到 Git 忽略的 `outputs/capability-evidence/`。记录只包含服务身份、Base URL、Model、能力结果、来源和时间，不包含 Secret。重启后仅精确匹配三项身份的 Profile 会加载该记录。

## 验证范围

本轮没有发起真实联网请求。Targeted Python 测试覆盖旧身份迁移、精确 Capability 绑定、普通请求 gate、Probe 临时放行与持久化精确范围；浏览器测试覆盖实际 Capability 状态显示。修改未涉及 RAG、Grounding 或 Streaming 数据流实现。
