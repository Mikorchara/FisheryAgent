# V0.1.1-A3.0.4：Custom Profile Manager

## 已实现

开发验证页面的模型配置区增加 **Qwen、DeepSeek、Custom OpenAI-compatible** 三个预设。选择预设会填写 `provider_id`、`adapter_id`、Base URL、推荐的 `secret_env` 名称和示例模型。Custom 预设使用可修改的本地 `http://localhost:11434/v1` 作为起点，不代表绑定 Ollama。用户可手动修改 Base URL 与 Model ID；普通模式不必输入 `provider_id`。

简单模式显示 Provider、当前进程 Secret 状态、Base URL、Model、Display Name、模型查询、连接测试与保存。高级模式才显示 `provider_id`、`adapter_id`、`secret_env` 和 Cloud/Local 类型。页面只显示环境变量名及 `PRESENT/MISSING`，不提供真实 Key 输入框；本地 `.env` 仅在 Web 启动边界加载。修改 `.env` 后需要重启服务。

“查询可用模型”按钮显式调用当前 OpenAI-compatible Adapter 的 `/models`，只将允许显示的模型 ID 返回页面并填入下拉框。原模型文本框始终可手动输入；接口不支持模型列表时无需放弃该服务。列表成功只说明接口响应，不表示 Streaming、Reasoning、结构化输出或 Tool Calling 已验证。

“测试连接”默认使用不生成正文的模型列表接口，并检查当前 Model 是否在列表中。若服务不支持列表，用户可**另行主动选择**“最小 Chat”，页面先提示可能产生费用，再发送一次“只回复 OK”的真实请求。单次操作不自动回退或重试；返回成功/失败、模型、耗时和安全错误码，绝不返回模型正文、SDK 原始异常或 Key。Cloud Profile 保存前要求当前连接字段的一次成功测试；服务端发放 10 分钟内有效的短期测试凭据。修改 Provider、地址、Model、Secret 环境变量名或部署类型后，须重新测试。Local Profile 可不测试而保存，但真实测试仍可由按钮发起。

保存时检查显示名冲突，以及完全相同的 Provider + Base URL + Model。冲突时页面提供“更新原配置 / 另存为副本 / 取消”；相同连接优先建议更新。内置配置不能编辑或删除；自定义配置可以载入修改，也可删除。删除会将原 JSON 移入同一 Git 忽略目录下的 `archive/`，便于手工恢复。自定义配置继续保存在 `outputs/custom_profiles/custom-*.json`，只含连接设置及环境变量名，不含 Secret 值。不会修改包内预置 Profile。

## 技术边界

页面的 Profile 管理接口与现有 Orchestrator 分离；分析、RAG 和 Grounding 逻辑未改。模型查询将 SDK Adapter 现有的 `list_models` 扩展为可选返回本次响应的模型 ID，保留原默认行为。真实请求只由模型查询或连接测试按钮触发；页面加载、Secret 状态读取、Profile 保存与全部自动测试均不向 Provider 发请求。SDK 与 Gateway 重试仍为 0。

`/models` 不一定受所有 OpenAI-compatible 服务支持；最小 Chat 可能收费，且仅验证最基本生成连接。测试凭据仅存在当前 Web 进程内，重启后需重新测试。当前单用户本机页面没有登录、在线能力发现、Profile 导入导出或自动模型同步；高级 Capability 仍为 UNKNOWN。
