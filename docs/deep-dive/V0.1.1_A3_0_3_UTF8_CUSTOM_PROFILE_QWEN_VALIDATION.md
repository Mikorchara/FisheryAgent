# V0.1.1-A3.0.3：UTF-8 记录、CUSTOM Profile 页面与 Qwen Grounding 复测

## 修改

上轮请求已经完成，但验证脚本直接向 Windows 默认 GBK 终端打印模型中文内容，遇到无法编码的字符后丢失了结果。本轮新增显式验证脚本 `scripts/validate_qwen_grounding.py`：仅在 `--confirm-network` 下运行；先确认 Secret 为 `PRESENT/MISSING`，并要求 Qwen Profile 重试数为 0；一次页面分析请求后，以 `encoding="utf-8"`、`ensure_ascii=False` 写入新的 `outputs/qwen-grounding-*.json`。终端只输出 ASCII 状态和文件路径，不依赖终端编码。记录位于 Git 忽略的 `outputs/`，包含观察事实、规则、RAG Evidence、结构化模型结果、原始模型正文、Usage 和耗时，不含 API Key 或完整 Prompt。核心 Orchestrator/Gateway 未改。

CUSTOM Profile 页面标明必填/可选字段、各字段用途和示例，并说明示例不会自动填入。`provider_id` 要求小写机器标识；Cloud 的 `secret_env` 必填，Local 可选；这里只能填写如 `DASHSCOPE_API_KEY` 的环境变量名，绝不填写 Key。客户端在保存前提示常见缺失；服务端返回安全的 `field`、`reason` 和固定说明，不回显提交值。自定义配置仍存于 Git 忽略的 `outputs/custom_profiles/`，重启后加载。A3.0.2 的 RAG 与 Prompt Grounding 修正保持不变。

## 尚存问题

模型建议中出现“每 2 小时复测”“1 小时内升至 3.0 mg/L”“换水不超过 20%”等具体操作数值；当前规则与本次证据**没有直接给出这些时限或换水比例**。这类细节仍是模型建议，不能作为经过确定性验证的现场操作标准。此次不再修改 Prompt 后重发请求，以遵守一次真实请求限制。后续应建立针对建议数值与证据关系的离线评估，再决定是否加强合同或提示词约束。
