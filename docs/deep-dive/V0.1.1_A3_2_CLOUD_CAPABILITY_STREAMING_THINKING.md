# V0.1.1-A3.2：Cloud Capability、Streaming 与 Thinking

查询与实施日期：2026-10-01。以本轮读取的源码和官方资料为准。

## 1. 当前总体架构与审计

```text
Profile 精确 Identity
  → 官方声明 / 本机 Capability Evidence
  → 已保存 Runtime Defaults
  → 本次 Runtime Options / 不可变 RuntimeSnapshot
  → CapabilityValidator
  → OpenAICompatibleAdapter → OpenAI SDK
  → Provider

显式 Probe → 同一 Gateway / Adapter → 精确 Evidence → 页面刷新能力与选项
```

CODE-CONFIRMED：原有 service、adapter、规范化 URL、精确 model 身份绑定已存在；名称和 model_family 未作为证据键；首次 Streaming Probe 的 MouseEvent 问题已经修复。本轮保留这些行为。

本轮审计发现并修复：

- Thinking Probe 和记录保存仅接受 Ollama，Cloud 映射与验证入口脱节。
- 独立 Streaming/Thinking 状态未表达组合兼容性。
- 实机证据覆盖官方/metadata 的来源，无法在页面保留双方依据。
- 能力拒绝会改写已有 Thinking 默认偏好；默认回退仅在 Web 内处理。
- Normal 只记录 reasoning_present；应用 Streaming 忽略已有 reasoning_delta。
- Probe 缺少 delta、TTFT、Usage 等统一指标；Thinking 参数明确拒绝未单独分类。
- Probe 完成后的异步刷新可能重新选中较旧 Profile。
- Mock 的公开 Streaming 能力缺少声明，页面不能通过能力选项选择离线流式演示。

未发现本轮需要改写 RAG、Grounding 或领域规则的原因；这些逻辑没有改动。

## 2. Profile Identity

证据键固定为 `service_id + adapter_id + normalize_base_url(base_url) + exact model`。
规范化只处理 scheme/host 大小写和结尾斜杠，不将不同端口、路径、localhost/127.0.0.1 合并。
`/v1` 与 `/v1/` 相同；`/v1` 与空路径仍是不同身份。

预置 Profile 连接配置不可编辑；Custom 连接改变后只加载新身份的记录。同名家族、相似模型、URL 关键词不能继承验证结果。两个配置确实具有完全相同身份时可以共享该身份的证据。

## 3. Evidence Model

状态：SUPPORTED / UNSUPPORTED / UNKNOWN。
来源：OFFICIAL_DOCS / MODEL_METADATA / USER_VERIFIED / UNKNOWN。

`source_for()` 返回当前状态来源；新增不可变 `evidence_sources` 与 `sources_for()` 保存来源列表。
本机最新显式验证结果决定当前状态，但官方/metadata 来源继续显示。来源列表不是完整审计日志；重复 Probe 保存每项能力的最新记录。

官方声明在 `official_capabilities.py`，是离线、手工核实的精确模型/端点表。无后台在线发现。
本机记录在 Git ignored 的 `outputs/capability-evidence/`，每项能力独立文件。Custom 连接配置仍在 `outputs/custom_profiles/`，不写 Secret 值。

## 4. Qwen 官方研究

本轮安全读取当前 Custom Profile 的 service/adapter/model，确认还存在 `qwen3.8-flash` 和 `qwen3.8-omni-flash`，因此一并研究。

| DashScope 精确模型 | Thinking 默认 | ON/OFF 协议 | 本次提供的 Effort |
|---|---|---|---|
| qwen-plus | OFF | enable_thinking=true/false | UNKNOWN；不猜档位 |
| qwen3.8-flash | ON | enable_thinking=true/false | low / medium / xhigh |
| qwen3.8-omni-flash | ON | reasoning_effort；none 关闭 | low / medium / xhigh |

这些模型的 Streaming 和 Thinking + Streaming 有官方调用依据；声明为 SUPPORTED · OFFICIAL_DOCS。
商业模型的同步输出受到官方说明支持；仍需本机验证延迟与具体输出。Qwen 返回 reasoning_content 与 content；Usage 可提供 reasoning_tokens。流式请求通过 include_usage 获取用量包。

Qwen3.8 的兼容别名不作为本项目通用档位；不实现 thinking_budget，因此不会产生其与 effort 的组合冲突。Omni 的 ON 未指定 effort 时，Adapter 使用该精确协议的官方默认 xhigh；这不是系统通用 ON=HIGH 规则。[深度思考](https://help.aliyun.com/zh/model-studio/deep-thinking)、[OpenAI兼容-Chat](https://help.aliyun.com/zh/model-studio/qwen-api-via-openai-chat-completions)、[Qwen-Omni](https://help.aliyun.com/zh/model-studio/qwen-omni)。

## 5. DeepSeek 官方研究

精确范围：DeepSeek 官方服务 `deepseek_api` 的 `deepseek-flash`，不涉及百炼托管版本。

默认 Thinking ON，默认 effort high。Thinking 开关使用 thinking.type=enabled/disabled；本次 Effort 只列 low/high/max，不统一出 medium。AUTO 不发送控制参数；OFF 不允许同时设置 effort。

Streaming、Thinking ON/OFF 和组合声明为 SUPPORTED · OFFICIAL_DOCS。reasoning_content 与 content 分离，Usage 的 completion_tokens_details.reasoning_tokens 是可选推理计数。include_usage 用于流式统计；DeepSeek 用量附在最终内容块，不能假设一定有独立空 choices 用量包。Adapter 两种格式均可读取。Thinking 下 temperature 不生效，记录该冲突约束；其他采样能力本轮仍保守处理。[Thinking Mode](https://api-docs.deepseek.com/guides/thinking_mode/)、[Chat Completions API](https://api-docs.deepseek.com/zh-cn/api/create-chat-completion/)。

## 6. Adapter 映射

上层只使用 ReasoningOptions(AUTO/ON/OFF, effort) 与响应模式。

| 服务/精确模型 | Adapter 请求映射 |
|---|---|
| DashScope qwen-plus、qwen3.8-flash | extra_body.enable_thinking；effort 若支持则为 SDK 顶层 reasoning_effort |
| DashScope qwen3.8-omni-flash | SDK 顶层 reasoning_effort：OFF=none；ON=显式 effort 或 xhigh |
| DeepSeek 官方 deepseek-flash | extra_body.thinking.type；SDK 顶层 reasoning_effort |
| Ollama qwen3.5:4b | 保留原映射：reasoning_effort=high/none |
| 未知协议映射 | 不猜字段；显式 Thinking 返回安全错误 |

AUTO 在所有映射中省略开关与 effort。Provider 参数名只在 Adapter 翻译；官方声明表属于配置依据，Web 和 Orchestrator 不翻译这些参数。SDK 自动重试保持 0；Gateway 的既有“输出开始后不重新生成”规则保留。

## 7. Streaming Probe

用户按钮确认 REAL NETWORK REQUEST 后，通过 `/api/profiles/<id>/probe` 执行统一 `run_capability_probe()`。
一次最小“只回复 OK”请求，generation UNSET、reasoning AUTO、retry=0，不执行 Fishery 分析。
必须收到非空 content delta 并正常返回；仅 reasoning delta 不算 Streaming Probe 成功。

返回/保存 delta_count、reasoning_delta_count、TTFT、content TTFT、latency、Usage（不存在则 unavailable）和安全错误码。
Probe 的 TTFT 是首个 reasoning 或 content 增量；content TTFT 单独记录。普通应用 TTFT 仍为首个最终正文增量。

## 8. Thinking ON/OFF Probe

`/thinking-probe` 接受 mode=on/off；两次验证需分别点击，不自动批量执行。
临时能力只对本次专用 Probe 生效，不改正式请求门禁。
每次一个最小同步请求，retry=0。返回非空最终文本后写入对应 reasoning_on 或 reasoning_off 的 USER_VERIFIED 记录。

OFFICIAL_DOCS/MODEL_METADATA 的能力允许第一次实机验证；只有已存在 USER_VERIFIED 才进入“重新验证”。ON 成功不能改变 OFF 状态。
网络失败不写新的拒绝记录；已有官方或历史实机结论也不会因网络失败丢失。

## 9. Streaming + Thinking Probe

单独使用 thinking_streaming_combination 状态和证据。只有独立 Streaming、Thinking ON 已支持时开放按钮。
一次显式 ON + Streaming 的最小请求，retry=0；必须收到最终正文增量并正常结束，统计可选 reasoning delta，不要求 Provider 暴露推理文本。
组合成功/拒绝只更新组合记录，不把独立 Streaming 或 ON/OFF 结果一起改写。

普通 Streaming + ON（或 AUTO 且已知模型默认 ON）需要组合 Capability 支持；不能只根据两个独立状态推导。官方直接给出的组合调用依据可以作为 OFFICIAL_DOCS，与本机组合 Probe 分开。

## 10. Reasoning Content / Final Content

ModelResponse 增加可选 reasoning_content；ModelEvent 已有 reasoning_delta，应用现单独转发。
AnalysisResult 的 reasoning_content 保存开发调试内容；generated_text、Inference 和 JSON 解析只使用最终 content。
中途失败保留已收到的两类文本。Reasoning 不进入 JSONL Trace，也不用于业务正确性判断。
没有 reasoning 内容或 reasoning tokens 仍可正常完成。

## 11. UI 行为

“02 · 模型能力”统一展示 Streaming、Thinking ON、Thinking OFF、模型默认、Effort、组合、Structured Output、Tool Calling 及来源列表；同区提供本次运行选项。
SUPPORTED 可选；UNKNOWN/UNSUPPORTED 禁用且分别解释；AUTO/UNSET/Normal 始终是安全入口。
Probe 成功自动读取最新 Profile 数据，解锁对应选项；主验证按钮移入高级重新验证操作。
Profile 切换重新计算状态；Probe 刷新期间的切换不会被旧结果重新选回。
Reasoning 放在默认折叠的开发者调试区域，DOM 使用 textContent。
Built-in 基础配置/声明不允许页面修改；Probe 只增加本机独立证据。

## 12. Custom Profile 与 Runtime Defaults

未知 custom service 的高级能力保持 UNKNOWN；Normal + AUTO + generation UNSET 可运行。
显式 dashscope/deepseek_api，且 adapter、规范化端点、model 全部精确匹配时可以加载本轮官方声明。未知端点不因 URL 或模型名字相似继承官方声明。

通用 Custom 若没有已知 Thinking 协议映射，按钮禁用并说明原因；不能从名字推测参数去 Probe。Streaming Probe 仍可单独使用。
已保存偏好与 Capability 分离。UNKNOWN 或后来被证实不支持时，快照暂时回退 AUTO/Normal，保留已保存偏好；组合不可用也回退 Normal并提示。共享默认解析器同时供 Web 和快照使用。

## 13. Error Mapping

保留 OPTION_UNKNOWN / OPTION_UNSUPPORTED / OPTION_CONFLICT、CONNECT_TIMEOUT、READ_TIMEOUT、TLS_ERROR、PROXY_ERROR、HTTP_<status>、STREAM_INTERRUPTED。
只将明确的 Provider Streaming/Thinking 参数拒绝映射为 STREAM_UNSUPPORTED / THINKING_UNSUPPORTED；普通 HTTP 400、服务不可达、Timeout 不足以判定不支持。
Probe 无正文为 PROBE_NO_CONTENT；未分类内部失败为 CAPABILITY_PROBE_FAILED；记录失败为 CAPABILITY_RECORD_FAILED。
浏览器区分网络、非 2xx 安全码、JSON 格式错误、页面刷新错误；不显示原始异常或敏感 headers。

## 15. 尚未验证与限制

- 本轮未发送真实 Cloud/Ollama 生成请求，也未读取/打印 Secret 值。真实 Thinking ON、OFF 和组合效果需用户逐项确认。
- 请求成功证明精确端点接受该请求并返回回答；服务若静默忽略参数、又不返回推理文本，单次 Probe 不能证明内部推理状态。官方资料/metadata 与实机指标需要联合判断。
- 官方声明只覆盖本轮研究的端点与精确模型；新地域、workspace 专属端点或模型要单独核实并添加记录，不自动套用。
- 官方别名可能升级；查询日仅是本次声明的时间，后续应按官方更新和本机 Probe 维护。
- 证据保存最新状态与来源集合，不实现完整事件历史、撤销证据或跨进程管理 UI；当前仍是单进程开发验证工具。
- 不实现 Tool Calling、Structured Output Probe、Agent、Memory、Fine-tuning、Vector DB、Failover 或自动在线能力发现。
- RAG、Grounding、确定性规则、正式项目未修改；未 commit/push。
